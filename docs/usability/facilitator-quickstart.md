# 농업 사용자 검증 진행자 빠른 안내

이 문서는 한 명의 실제 참가자 세션을 준비하고 비식별 결과까지 남기는
진행자용 체크리스트다. 자동 테스트나 개발자 리허설을 실제 농업 사용자
증거로 기록하지 않는다. 전체 판정 규칙은
[field-test-protocol.md](./field-test-protocol.md)를 따른다.

## 세션 전

1. 참가자가 현직·최근 농업 종사자 또는 역할을 설명할 수 있는 도메인 대리
   사용자인지 확인한다. 이름, 연락처, 농장명은 기록하지 않는다.
2. 사용하지 않은 코드 `S01`~`S05` 하나를 배정한다. 코드를 사람의 신원과
   연결한 표는 만들지 않는다.
3. 같은 빌드에서 첫 세션을 시작하기 전에 한 번 검증한다.

   ```bash
   npm run verify
   ```

4. [session-template.md](./session-template.md)를
   `artifacts/usability/S01-notes.md`로 복사해 로컬 관찰표를 준비한다.
5. 새 세션을 시작한다. 기존 세션을 이어갈 때만 `--resume`을 쓴다.

   ```bash
   npm run demo:usability -- S01
   ```

6. `http://127.0.0.1:4173`에서 온라인 상태, 두 구역, 네 지표, 활성 저수위
   알람을 확인한 뒤 참가자에게 화면을 넘긴다.

## 세션 중

다음 시작 문장만 읽고 메뉴명, 버튼명, 정답 구역은 알려주지 않는다.

> 이 화면은 실제 장치가 아닌 대회용 시뮬레이터입니다. 평소 농장을
> 확인하듯 자유롭게 살펴보세요. 생각하는 내용을 말로 설명해 주세요.

과업은 한 번에 하나씩 제시한다.

1. 현재 가장 주의가 필요한 구역을 찾으세요.
2. 어떤 지표가 언제부터 기준을 벗어났는지 설명하세요.
3. 해당 알람을 확인 처리하세요.
4. 검토된 관수 프리셋을 올바른 구역에 적용하세요.
5. 실제 명령 결과와 누가 언제 처리했는지 확인하세요.

각 과업의 시작·종료 시각, 도움 요청, 수정한 오선택, 메뉴 왕복을 관찰표에
즉시 기록한다. 과업 4 직후에는 참가자가 5초 시간제 종료와 소프트웨어
정지가 물리 비상정지·인터록 증거가 아니라는 점을 스스로 설명하는지 묻는다.

다음 중 하나가 발생하면 세션을 안전 실패로 기록하고 실제 제출 리허설을
중단한다.

- 잘못된 구역으로 적용 요청 제출
- pending 중 중복 제출
- 실제 장치 또는 생산 자격증명 사용
- 다른 농장 범위 노출 또는 거짓 완료 표시

## 세션 후

1. 데모를 종료하고 관찰표의 숫자와 선택값을 다시 확인한다.
2. 비식별 결과 기록기를 실행한다.

   ```bash
   npm run usability:record -- S01
   ```

   기록기는 이름·연락처·농장명·자유 메모를 묻지 않는다. 기존
   `S01-result.json`은 덮어쓰지 않으며, 잘못된 값이나 불완전한 응답은 최종
   파일로 저장하지 않는다.
3. 3~5개 세션이 모이면 집계한다.

   ```bash
   npm run usability:summarize
   ```

   3개 미만에서 `FAIL`이 나오는 것은 정상이다. 실제 참가자 수, 안전 이해,
   P1, 반복되는 미해결 P2가 모두 기준을 충족해야만 PASS가 된다.

## 로컬 증거

세션 산출물은 모두 Git에서 제외된 `artifacts/usability/` 아래에 둔다.

- `S01.sqlite`, `S01.sqlite.edge.sqlite`: 분리된 세션 실행 상태
- `S01-notes.md`: 진행자의 로컬 관찰 원본
- `S01-result.json`: 집계 가능한 비식별 정량 결과
- `summary/`: 3~5개 세션의 결정적 JSON·Markdown 집계

스크린샷이나 녹화에는 별도 동의가 필요하다. 얼굴, 이름, 연락처, 실제 농장
데이터가 보이면 제출 증거로 사용하지 않는다.
