# 국내 스마트팜 표준·데이터·현장 적용 조사

- 조사 기준일: 2026-08-12
- 대상: SmartFarmOS의 국내 시설원예 상호운용성, 데이터 연계, 현장 검증 방향
- 근거 범위: 농림축산식품부, 한국농업기술진흥원, 국가표준·공공데이터 포털, 농촌진흥청 및 공공 실증기관의 공개 자료
- 제외: 표준 원문을 확보하지 않은 상태에서의 세부 레지스터 추정, 인증·검정 획득 주장, 특정 업체 비공개 프로토콜 복제

## 결론

SmartFarmOS가 국내에서 내세울 가장 현실적인 개방성은 “모든 장비를 바로 지원한다”가 아니라 다음 세 단계다.

1. **SmartFarmOS 내부 계약은 엄격하고 제조사 중립적으로 유지한다.**
2. **현장 Edge에 KS 계열 센서·구동기 어댑터를 추가할 수 있는 경계를 둔다.**
3. **국내 표준 데이터로 내보내거나 비교할 수 있는 별도 프로파일을 제공한다.**

정부의 2026년 시행계획도 기자재 간 물리·통신 규격 차이로 유지보수가 어려워졌다고 진단하고, 표준 적용 기자재의 농가 실증을 2025년 누적 159호에서 2026년 누적 359호로 확대하는 방향을 제시한다. 이는 “개방형 Edge 어댑터 + 검증 가능한 데이터 계약”이 국내 SmartFarmOS의 장기 제품 방향으로 타당하다는 정책 근거다. 다만 현재 대회 MVP는 시뮬레이터 기반이므로, 문서와 시험 설계 없이 실장비·표준 호환을 주장해서는 안 된다. ([농림축산식품부 2026년 스마트농업 육성 시행계획](https://www.mafra.go.kr/bbs/home/791/594105/download.do))

## 국내 표준 지형

| 표준·자료 | 공개 확인된 범위 | SmartFarmOS 적용 판단 |
| --- | --- | --- |
| KS X 3265 | 스마트 온실 구동기 인터페이스 | `Device` capability와 Edge actuator adapter의 장기 호환 프로파일로 **변형 채택** |
| KS X 3266 | 스마트 온실 센서 인터페이스 | metric/unit/quality/calibration 메타데이터의 장기 호환 프로파일로 **변형 채택** |
| KS X 3267 | 센서·구동기 노드와 통합 제어기 사이 RS485 Modbus 인터페이스 | Edge의 실장비 transport adapter와 적합성 시뮬레이터 대상으로 **대회 후 채택** |
| KS X 3268 | 스마트 온실 구동기 메타데이터 | 실행 가능한 플러그인이 아닌 data-only 장치 메타데이터로 **대회 후 검토** |
| KS X 3269 | 스마트 온실 센서 메타데이터 | 센서 유형·단위·교정·품질 확장의 근거로 **대회 후 검토** |
| SPS-X KOAT-0009-7470 | 시설·영농·환경·제어 등 시설원예 수집 데이터의 이름·형식·단위 | 내부 모델을 교체하지 않고 export/import profile로 **우선 검토** |

국가표준 확산사업 포털은 KS X 3265, 3266, 3267의 명칭을 공개한다. 다만
index에는 `2026-01-19`, 같은 공식 계열의 상세 페이지와 RRA 문서에는
`2022-01-11`이 표시되어 최종 개정확인 날짜는 단정하지 않는다. KS X 3267
시험 방법을 공개한 한국농업기술진흥원 자료는 이 표준이 센서/구동기 노드와
온실 통합제어기 사이의 상호연동을 위해 RS485 Modbus 인터페이스를 정의한다고
설명한다. 즉 이 표준은 브라우저 API가 아니라 **현장 장치와 통합제어기
사이의 어댑터 경계**에 가깝다. ([국가표준 목록](https://www.smartfarm-standard.kr/standard/guide/record/index.php?page_num=2), [KS X 3267 시험 방법](https://www.koat.or.kr/board/standard_doc/11807/view.do), [독립 검증 메모](standards-validation.md))

SPS-X KOAT-0009-7470은 시설원예 스마트팜의 경영체, 시설, 영농, 환경, 제어 공통데이터에 대해 앨리먼트명·타입·단위 등을 규정한다. 농림축산식품부 기본계획도 이 규격을 시설원예 데이터 수집 단체표준으로 명시하고, 스마트팜코리아 연계 데이터가 단체표준에 맞게 축적되도록 메타데이터와 데이터 항목을 재정의하는 방향을 제시한다. 따라서 이 규격은 SmartFarmOS의 내부 도메인을 통째로 바꾸기보다 **교환 프로파일과 매핑 테스트**에 쓰는 편이 유지보수에 유리하다. ([국가표준인증 종합정보센터](https://www.standard.go.kr/KSCI/ct/ptl/prvntc/curstat/detail.do?currentPageNo=1&grpStdSn=18386&pageSize=10&recordCountPerPage=10&searchText=&searchType=1), [한국농업기술진흥원 표준 정보](https://www.koat.or.kr/board/standard_doc/11813/view.do), [제1차 스마트농업 육성 기본계획](https://www.mafra.go.kr/bbs/home/792/584835/download.do))

## 현재 코드와의 연결

### 유지할 내부 계약

현재 `packages/contracts/src/telemetry.ts`는 metric, unit, sequence, observedAt을 엄격히 검증하고 `services/edge/src/gateway.ts`는 farm/device scope를 확인한 뒤 중앙 API로 전달한다. 이 구조는 버리지 않는다. 표준 원문의 필드와 레지스터를 중앙 계약에 직접 노출하면 장치별 차이가 PWA와 API까지 전파되기 때문이다.

권장 경계는 다음과 같다.

```text
KS/제조사 장치
  -> 현장 transport/codec adapter
  -> SmartFarmOS Telemetry/Command 계약
  -> 기존 Edge 검증·journal·ACK
  -> 중앙 API/PWA
```

### 필요한 장기 확장

- `DeviceTransportAdapter`: 연결, 읽기, 쓰기, 상태 확인을 담당하며 명령 의미나 farm 권한을 소유하지 않는다.
- `DeviceProfile`: data-only 센서·구동기·통신 capability와 제조사/모델/펌웨어 식별 정보를 담는다.
- `TelemetryQuality`: raw/validated/suspect/missing, 교정 시각, 센서 상태와 결측 이유를 표현한다.
- `StandardMappingProfile`: SmartFarmOS 필드와 KS/SPS 필드의 버전된 대응표다.
- `ConformanceFixture`: 실제 장치 없이 정상, 범위 초과, CRC/timeout, stale, partial-read, actuator no-response를 재현한다.

이 항목들은 새 런타임 플러그인 시스템이 아니다. 현재 module-sdk의 data-only·allowlist 원칙과 동일하게 검토된 어댑터만 빌드에 포함해야 한다.

## 공공데이터 활용

농림축산식품부 스마트팜 데이터 마트 API는 농가·작기 식별정보와 환경·생육·제어 데이터를 JSON/XML로 제공한다고 설명한다. 온도·습도·CO₂, 양액·광·관수, 생육 단계 지표가 포함되므로 SmartFarmOS의 시뮬레이터 범위와 데이터 모델을 검토할 현실 자료 후보가 된다. 하지만 제공 설명만으로 결측률, 샘플링 간격, 품질 플래그, 농가별 센서 교정 차이를 확인할 수 없으므로 제어 기준값을 곧바로 학습하거나 제품 성능을 주장하는 데 사용하면 안 된다. ([공공데이터포털 스마트팜 빅데이터 API](https://www.data.go.kr/data/15121334/openapi.do))

권장 사용 순서는 다음과 같다.

1. API 약관·필드·호출 제한과 실제 샘플을 별도 검토한다.
2. 원본을 SmartFarmOS 내부 계약으로 직접 간주하지 않고 수입 DTO에서 검증한다.
3. 단위, 시간대, 결측, 중복, 센서 교체와 작기 경계를 먼저 프로파일링한다.
4. 통계·시뮬레이터 개선과 UX 검증에는 사용할 수 있지만, 물리 제어 안전성 근거와 분리한다.

## 현장 운영에서 드러난 요구

2026년 농촌진흥청 현장 교육은 환경제어 장치, 센서, 양액기의 구조와 이상 증상, 단순 설정 오류, 전기적 문제를 구분하는 점검 역량을 강조했다. 이는 현장 제품의 가치가 제어 버튼 수보다 **장비 상태, 진단 가능성, 점검 절차와 지원 인계**에 있음을 보여준다. SmartFarmOS는 향후 다음 운영 정보를 우선해야 한다. ([농촌진흥청 현장 전문가 교육](https://www.rda.go.kr/board/board.do?dataNo=100000811182&mode=view&prgId=day_farmlcltinfoEntry))

- 마지막 정상 관측·통신·ACK 시각
- 센서 범위 초과와 stale/flatline 상태
- Edge queue와 ACK outbox 상태
- 명령 대상·요청값·실제 최종상태·실패 이유
- 장치/어댑터/펌웨어 버전과 최근 교정·점검 시각
- 운영자가 수행할 수 있는 안전한 점검 절차와 설치자에게 넘길 진단 묶음

고흥 스마트팜 혁신밸리는 KS X 3267 적합성과 장비 간 호환성, 센서 정확성을 시험하는 복합환경 제어기 시험시스템을 공개하고 있다. 실제 호환 주장을 하려면 자체 시뮬레이터 통과만으로 끝내지 말고 이러한 공공 실증·검정 경로 또는 동등한 독립 시험을 계획해야 한다. ([고흥 스마트팜 혁신밸리 실증장비](https://ghsf.or.kr/info/equip.do?page=6))

## 대회 전과 이후의 결정

### 2026-08-27 대회 전

1. `KS X 3265~3269`, `SPS-X KOAT-0009-7470`을 장기 호환 목표로 문서에 기록한다.
2. 현재 SmartFarmOS 계약과 표준 개념의 향후 매핑 원칙만 기록하고 호환
   완료로 표시하지 않는다.
3. `stale`, `suspect`, `offline`, `recovery_required`는 대회 후 진단 확장의
   근거로만 사용하고 현재 PWA 범위를 늘리지 않는다.
4. 새 Modbus 라이브러리, 실제 장치 드라이버, 인증 주장을 추가하지 않는다.
5. 제출 문서에서는 “국내 표준과 연결 가능한 Edge 어댑터 구조”라고 설명하고 “KS 호환 제품”이라고 주장하지 않는다.

### 대회 후 파일럿

1. 표준 원문과 합법적으로 사용할 수 있는 레지스터/메타데이터 자료를 확보한다.
2. `DeviceTransportAdapter`와 KS X 3267 codec을 분리 구현한다.
3. 정상 통신뿐 아니라 timeout, 부분 프레임, 중복 응답, stale 센서, 구동기 무응답, 재부팅을 시험한다.
4. KS X 3265/3266/3268/3269와 SmartFarmOS 장치 프로파일 매핑을 버전화한다.
5. SPS-X KOAT-0009-7470 export fixture와 round-trip 검증을 추가한다.
6. 실제 표준 기자재 또는 검정 환경에서 적합성과 상호운용성을 독립 확인한다.

## 불확실성과 추가 확인

- 공개 포털의 요약만 확인했으며 KS 원문 전체의 필수·선택 조항과 레지스터 세부사항은 아직 검토하지 않았다.
- KS X 3265~3267의 공식 페이지 간 날짜 충돌을 포함해 표준 개정 이력,
  원문 이용 조건, 적합성 시험 비용과 신청 절차는 파일럿 전에 별도 확인해야 한다.
- 스마트팜 데이터 마트의 실제 응답 품질, 호출 제한, 개인정보·재식별 위험과 재배포 조건은 샘플 수집 전 확정되지 않았다.
- SmartFarmOS는 실장비·RS485·Modbus·KS 적합성 검증을 아직 수행하지 않았다.
