# 클라우드 제품화·출품 우선순위

확인일: 2026-08-24
대상: 2026 오픈소스 개발자대회 출품용 SmartFarmOS 공개 데모

이 문서는 승인된 클라우드 자원을 대회 제출과 검증에 어떻게 사용할지
정한다. 클라우드 배포는 공식 제출 파일의 필수 항목이 아니다. 결과보고서,
공개 소스코드, 3분 이내 시연영상이 먼저이며, 클라우드는 실사용 가능성,
데모 안정성, 기능 검증을 보강하는 증거다.

## 공식 제출·평가 기준

- 공식 마감: `2026-08-27 18:00 KST`
- 제출 ZIP: 결과보고서 원본, 같은 내용의 PDF, 해당 시 중복수혜 확인서
- 결과보고서: 대표 공개 저장소 URL 1개, 3분 이내 YouTube 영상 URL,
  필수 SBOM 포함
- 포털 완료: 파일 업로드 후 `출품작 제출 완료하기`를 누르고 `제출 완료`
  상태와 완료 안내 이메일을 모두 확인
- 제품에 AI 모델을 탑재하지 않고 코딩·디버깅 보조로만 상용 AI를 사용한
  것은 허용된다. 제품에 AI 모델을 탑재했다면 공개 수준과 독립 구동 조건을
  검토하고 붙임 2에 기재한다.

1차 서면 평가는 다음 다섯 항목을 각 6점, 합계 30점으로 평가한다.

| 항목 | SmartFarmOS 증거 |
| --- | --- |
| 프로젝트 구조·코드 완성도 | 타입 계약, API/Edge 경계, SQLite migration, 자동 검증 |
| 오픈소스 발전 가능성 | Apache-2.0, 기여 문서, 모듈 경계, 공개 로드맵 |
| 개발 문서 구체성 | README, 아키텍처, ADR, 배포·검증 문서 |
| 프로젝트 혁신성 | 장치 범위 인증, ACK 복구, 소프트웨어 정지 우선 경로 |
| 협업·관리체계 | 커밋, 이슈·리뷰 기록, 결정 문서, 재현 가능한 검증 |

2차 평가는 발표 10점, 활용성 15점, 데모 완성도 10점, 커뮤니티 확장
가능성 5점, 오픈소스SW 적절성 15점, 기능테스트 10점, 라이선스 검증
5점이다. 외부 HTTPS 데모는 이 중 활용성·데모·기능테스트의 직접 증거로
사용한다.

## 승인 클라우드의 확인된 경계

참가자 포털과 연결된 터미널에서 다음을 확인했다. 인스턴스 ID, 세션 ID,
IP와 자격증명은 저장소에 기록하지 않는다.

| 항목 | 확인 결과 |
| --- | --- |
| 상태 | 승인·운영 중, 이용기간 1개월 |
| 공급자 표시 | KT |
| OS·아키텍처 | Rocky Linux 8.10, x86_64 |
| 자원 | 2 vCPU, 메모리 15 GiB |
| 루트 디스크 | 17 GiB, 확인 시 약 13 GiB 사용 가능 |
| 컨테이너 | Podman 4.9.4 |
| 미설치 | Docker, Git, Node.js, npm, Caddy |

호스트에 Node.js와 Caddy를 설치하지 않는다. 공개 커밋의 소스 아카이브를
전달하고 Podman이 현재 `deploy/cloud-pilot/Dockerfile`을 빌드하도록 한다.
컨테이너만 Node.js, Caddy, PWA, API와 시뮬레이터를 포함한다.

아직 확인되지 않은 항목은 공인·고정 IP, 80/443 인바운드 정책, 도메인과
인증서 책임, 스냅샷·백업, 종료 시 반출·삭제, 연장 기준이다. 운영사 답변
없이 상용 SLA, 영구 호스팅 또는 자동 백업을 주장하지 않는다.

## 제출 전 P0

### P0-A: 클라우드와 무관한 필수 제출 게이트

1. `.codex`가 모든 이력에서 제외된 공개 대표 저장소를 실제 Public으로
   게시하고 고정 commit을 기록한다.
2. 권리·제3자 자산·자격증명·privacy·AI 고지를 최종 검토한다.
3. 실제 사용성 세션 3–5건을 기록하고 집계한다.
4. 3분 이내 최종 영상을 검수하고 YouTube URL을 확보한다.
5. SBOM을 포함한 원본 보고서와 동일 PDF를 ZIP으로 만든다.
6. 포털 업로드, `제출 완료` 상태, 완료 안내 이메일을 확인한다.

### P0-B: 시간 제한을 둔 클라우드 증거

1. 운영사에 공인 IP, 80/443, DNS, HTTPS, 백업, 종료·연장 조건을 확인한다.
2. 공개 commit SHA를 이미지 태그로 사용해 rootful Podman으로 빌드한다.
3. Caddy만 80/443에 공개하고 API 3100, PWA 4173, 관리자 4174는 공개하지
   않는다.
4. 날씨 API 키를 넣지 않고 결정적 fixture 모드를 사용한다.
5. HTTPS와 외부 Basic Auth 뒤에서 PWA → API → 시뮬레이터 → ACK 흐름을
   다른 네트워크의 브라우저로 확인한다.
6. 배포 commit, 이미지 태그, 점검 시각, `/healthz`, 복구 명령을 기록한다.

2026-08-25 18:00 KST까지 공인 접속 경로와 HTTPS를 확보하지 못하면
클라우드 작업을 중단하고 검증된 로컬 데모로 영상·보고서·포털 제출을 먼저
완료한다. 이 시각은 프로젝트 내부 중단선이며 공식 마감이 아니다.

## 공개 데모 범위

공개하는 것은 사용자 PWA와 시뮬레이터 데이터뿐이다.

- 포함: 두 구역 환경 비교, 알람 확인, 작물 관리, 관수 프리셋, ACK·감사 이력
- 제외: 관리자 콘솔, Edge 등록 자격증명, 실제 농가·사용자 데이터, 실제
  센서·릴레이, OpenWeather 실키, 물리 비상정지·인터록 주장
- 접근 제어: 대회용 임시 Basic Auth를 사용하고 Git, 영상, 공개 문서에
  비밀번호를 기록하지 않는다. 심사자 전달 방식과 제출 후 회전 시점을
  소유자가 정한다.

이 배포는 `contest staging`이다. 실제 농가 운영 서비스나 안전 제어 제품으로
표현하지 않는다.

## 제출 후 P1

- Podman systemd/Quadlet로 재부팅 복구를 검증한다.
- SQLite와 Caddy 데이터를 스냅샷하고 복구를 한 번 리허설한다.
- 이미지 태그를 commit SHA로 고정하고 이전 이미지로 롤백하는 절차를 둔다.
- 접근 로그의 보존·마스킹 정책과 외부 상태 점검을 추가한다.
- 대회용 Basic Auth와 데모 키를 회전한다.
- 클라우드 이용 연장 여부와 데이터 반출일을 기록한다.

## 실제 제품화를 위한 P2

- 실제 사용자 인증과 역할·농장 단위 권한
- 실제 Edge 어댑터, MQTT ACL, 오프라인 텔레메트리 버퍼
- 물리 인터록·비상정지와 장치 상태 재조정
- 운영 데이터베이스, 백업·복구 목표, 보존·삭제 정책
- 감사 가능한 로그, 지표, 알림, 장애 대응
- 실제 농가 데이터의 동의·비식별·최소수집 기준

P2는 대회 제출 전에 급히 추가하지 않는다. 현재 검증된 시뮬레이터 경계를
흐리거나 제출 안정성을 낮추기 때문이다.

## 운영사에 확인할 질문

1. 현재 자원의 정확한 종료일과 연장 기준은 무엇인가?
2. 공인·고정 IP와 80/443 인바운드, 외부 도메인·HTTPS 사용이 가능한가?
3. Podman 컨테이너와 root 권한 사용 범위는 어디까지인가?
4. 볼륨 스냅샷·백업·복구 지원과 종료 시 데이터 반출·삭제 절차는 무엇인가?
5. 이 무상 클라우드 자원 사용이 대회의 중복수혜 확인 대상 공공지원에
   해당하는가?

5번 답변을 받기 전에는 기존의 `중복수혜 없음` 기록을 자동으로 바꾸거나
확인서를 임의로 제출하지 않는다. 답변일과 요지만 기록한다.

## 완료 조건

- 공개 저장소의 고정 commit에서 fresh clone 검증이 통과한다.
- 외부 HTTPS 데모가 80/443만 사용하고 관리자·비밀값을 노출하지 않는다.
- 사용성 3–5건, 3분 이내 영상, 원본·PDF·SBOM이 같은 배포본을 설명한다.
- 클라우드가 실패해도 로컬 검증본으로 마감 전 제출할 수 있다.
- 포털이 `제출 완료`이고 완료 안내 이메일을 수신한다.
