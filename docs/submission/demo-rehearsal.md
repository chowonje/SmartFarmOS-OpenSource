# 3분 시연영상 리허설

목표 길이는 165초이다. 공식 180초 제한을 맞추기 위해 전환·장애 버퍼
15초를 남긴다. 배속 후 시간이 아니라 최종 인코딩 파일의 실제 길이를
측정한다.

## 실제 PWA 검토용 후보 자동 생성

수동 녹화 전에 아래 명령으로 약 75~90초의 무음·자동 자막 후보를 만들 수
있다.

```bash
npm run submission:video-draft
```

명령은 새 임시 DB와 헤드리스 Chrome을 사용하고, 두 구역 비교, 저수위
알람 확인, 시간제 관수의 최종 off, 소프트웨어 정지와 물리 안전 한계,
인과 이력, 감사 이벤트가 실제 DOM에 모두 나타난 경우에만
`artifacts/submission/smartfarm-demo-candidate.mp4`를 만든다. 데스크톱 전체를
녹화하지 않으므로 개인 알림이나 다른 창은 포함하지 않으며, 기존 후보는
덮어쓰지 않는다.

이 파일은 촬영 순서와 실제 화면을 준비하는 **검토용 후보**일 뿐이다. 무음
트랙과 자동 자막이므로 필요한 나레이션·편집을 추가하고, 개인정보·화면 값·
주장 정확성을 사람이 처음부터 끝까지 확인해야 한다. 이 명령은
`video-proof.json`을 만들지 않으며 `--reviewed`를 받지도 않는다. 직접
녹화하거나 후보를 편집한 최종본에는 아래 165초 시나리오를 적용한다.

## 녹화 전 초기화

1. 화면 해상도를 1440×900 또는 1920×1080으로 고정하고 개인 알림을 끄다.
2. 참가자 코드 `S01`–`S05`와 겹치지 않는 리허설 코드를 사용한다.

   ```bash
   npm run verify
   npm run demo:usability -- S90
   ```

3. `http://127.0.0.1:4173`에서 작물 운영 화면을 연다.
4. 2번 베드 저수위 알람이 활성인지, 두 구역의 4개 지표가 있는지,
   제어 이력에 이전 리허설 데이터가 없는지 확인한다.

사용성 세션 실행기는 실시간 지표를 계속 갱신하면서 저수위 시나리오를
기본 약 10분간 유지한다. 이 설정은 새 익명 세션의 첫 탐색 과업을 위한
것이며 실제 농장 제어 로직이 아니다.

## 165초 시나리오

| 구간 | 화면·행동 | 나레이션 핵심 | 반드시 남길 증거 |
| --- | --- | --- | --- |
| 0–15초 | 제목 + 작물 운영 | “중소형 온실의 다구역 상태부터 장치 결과까지 한 흐름에서 확인합니다.” | simulator-backed contest MVP 문구 |
| 15–45초 | 두 구역 비교 | 2번 베드의 수위가 낮고 알람 기준을 벗어남 | 8개 지표, 수위 값, 관측 시각 |
| 45–70초 | 알람 센터 | 임계치, 최근 관측, 확인 상태가 분리됨 | 2번 베드·수위·미확인 |
| 70–85초 | 알람 확인 | 사용자 확인은 멱등적이고 감사 기록을 남김 | 확인됨 + 알람 감사 이벤트 |
| 85–120초 | 관수 전략 | 2번 베드만 선택하고 저수위 근거, 5초 장치 로컬 종료, 물리 안전 미검증을 확인 | 오구역 경고, 근거, 확인 체크 |
| 120–145초 | 적용·ACK | 시뮬레이터 장치가 5초 실행 후 최종 off를 확인한 뒤 ACK함 | pending, 대상별 최종 off, 적용 완료 |
| 145–160초 | 감사·최근 제어 | actor, 시각, 명령/전략 결과와 `농장 공통 제어` 수동 기록이 남음 | cycle-scoped V1 + unscoped direct-command V2 audit |
| 160–165초 | 한계 카드 | “완료 ACK의 Edge 재시작 복구까지 구현했지만 실행 중 장치 상태 복구·물리 인터록·MQTT·실장비는 파일럿 게이트입니다.” | 구현/미구현 범위 명시 |

## 장애 시 대처

- 알람이 이미 해제됨: 새 리허설 코드로 재시작한다. DB를 임의로 지우거나
  현재 세션을 새 세션으로 위장하지 않는다.
- 적용 상태 조회 실패: 접수된 pending이 보존되는 것을 보여주고 새로고침으로
  결과 조회만 재개한다. 중복 적용하지 않는다.
- ACK 업로드 실패: Edge 저널의 저장 결과만 재전송하고 장치 명령을 반복하지
  않는 테스트 증거를 제시한다. 영상에서 실제 장애를 즉흥 재현하지 않는다.
- 브라우저·API 재시작 필요: 녹화를 중단하고 새 코드로 전체 리허설한다.

## 녹화 후 검수

- [ ] 최종 파일이 180초 이하다.
- [ ] 이름, 연락처, 농장명, 브라우저 개인 알림, 로컬 경로가 보이지 않는다.
- [ ] 화면 값과 나레이션이 일치한다.
- [ ] 시뮬레이터 시간제 종료와 물리 인터록·실장비 미검증의 차이를 명확히 말한다.
- [ ] 최종 파일을 `artifacts/submission/` 아래에 두었다.

위 항목을 사람이 모두 확인한 뒤에만 다음 명령으로 최종 인코딩 파일의 실제
길이와 SHA-256을 측정한다. `--reviewed`는 스크립트가 영상을 이해했다는 뜻이
아니라, 사람이 개인정보·화면 값·나레이션·과장 표현을 검토했다는 명시적
확인이다.

```bash
npm run submission:video-proof -- artifacts/submission/smartfarm-demo.mp4 --reviewed
```

명령은 180초를 넘거나 허용 폴더 밖에 있거나 이미 증빙 파일이 있으면 새
`video-proof.json`을 만들지 않는다. 영상을 다시 인코딩했다면 기존 증빙을
보관하거나 제거한 뒤 최종 파일에 대해 다시 실행한다.
